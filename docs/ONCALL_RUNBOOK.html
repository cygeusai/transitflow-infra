Operations & On-Call Runbook

What every automated system does, what its signal means, and exactly what to do when it fires · July 25, 2026

First 15 minutes when something looks wrong

  1. Open the live status page: /functions/v1/tf-status. It shows every component and true availability, refreshing each minute.
  2. Check Slack for the latest System Health and Integration Watchdog posts. They name the exact component, error, and remediation.
  3. Open ClickUp Roadmap & Ops. Every issue needing a human is a tracked ticket with the fix written in it.
  4. Match the signal to the response table below and act. Most conditions self-heal; your job is the credential and dashboard actions the platform cannot do itself.

Integration queue watchEvery health checkGrades queued work across five states: dead, stranded, skipped, discarded, stuck in flight. Platform-wide, so orphaned rows in any tenant stay visible.

Auth-class vs config-class matters: only a credential rejection degrades a connector. A Slack channel-not-found, an invalid SMS destination, or a 404 on one record is a configuration or data problem and is deliberately excluded, so the status page never cries wolf.

Signal → response

SignalMeaningResponse
Health: degradedA non-critical component needs attention; platform is available.Read the component detail. If it names a connector reauth, action the matching ticket. No emergency.
Health: outageA critical path is down (e.g., data pipeline failing, PM conversions stuck).Treat as incident: open the IR plan, identify the down component, follow its playbook, communicate status.
Watchdog: escalationAn integration error has persisted past 72h; a ticket was auto-opened.Action the ticket. The connector self-clears once the credential is fixed.
Control: failingA governance control dropped below standard; urgent ticket auto-opened.Open the ticket; the fix and framework mapping are in it. Control auto-passes on next evaluation once remediated.
Security: gap > 0A new privilege drift or RLS gap appeared.Auto-harden runs every 6h and usually closes it. If it persists, inspect security_events and tf_security_scan().
Data quality: issueAn integrity check found orphans or math drift.Run tf_data_quality_audit() for detail; fix the flagged records.
Scheduler: job stalledA pg_cron job has not fired in 3× its cadence. One stalled job is a degradation; 3+ is a scheduler-wide outage.Run tf_scheduler_health() and read the named job. A ticket is already open. If the job is obsolete, unschedule it; the registry cleans itself up.
Queue: stranded / skippedIntegration work is stuck. Stranded still has retry budget but nothing is retrying it. Skipped was dropped by the worker with no retry path.Inspect with tf_queue_health(). Replay with tf_queue_requeue('stranded'), or retire with tf_queue_discard(). Requeue automatically holds back any provider whose credential is currently rejected.
Connector: reauth_requiredAn API token expired or was revoked.Rotate/reconnect the credential (owner action). A priority-2 ticket is opened on first detection, not after 72h, because this failure never recovers on its own. The worker self-heals and closes the ticket on the next successful call.

What fixes itself (do not intervene)

  • Recovered connectors: the watchdog and the integration primitive resolve the error, flip status to connected, and close the ticket automatically once a credential works again. All five connectors (QuickBooks, ClickUp, Slack, Twilio/Meta, Housecall Pro) report through the same primitive, so none can fail authentication while its health component stays green.
  • Privilege drift: auto-harden revokes anon/public execute on new SECURITY DEFINER functions every 6 hours.
  • Finance token expiry: QuickBooks sync degrades cleanly and resumes on reconnect, resolving its own error.
  • Duplicate tickets: the registry de-duplicates, so a standing issue never files twice.
  • Transient job failures: a single job startup timeout in 24h is graded flaky, not failing, and does not ticket. Escalation needs 2+ failures or a currently-failed last run, so worker contention never trains you to ignore the signal.
  • Newly scheduled jobs: a job created minutes ago has no run history. It is graded awaiting first run, not stalled, until one full cadence window has passed.
  • Queue backoff: retryable events with budget remaining are left alone. Only work with nothing retrying it (stranded) or nowhere to go (dead, skipped) reaches you.
