Automated data-quality monitoring

Added tf_data_quality_audit(), which continuously checks six integrity signals: referential orphans, stuck maintenance conversions, stale processing payments, owner-statement math mismatches, duplicate Housecall Pro jobs, and active leases with no tenant. It returns a structured report and a total issue count, and is wired into the platform health check as a dedicated Data Quality & Integrity component. If any integrity issue ever appears, it surfaces in isolation on the status page and the Slack health post, so it is caught before it reaches a report or a customer. Current state: 0 issues.

Indexes added

lease_ledger: lease_id, owner_id, unit_id (FK-leading) · maintenance_requests: lease_id, work_order_id · owner_statements: owner_id · rental_applications: unit_id. These accelerate the ledger, statement, and render-engine joins that filter by a single foreign key, and they speed foreign-key maintenance as these tables grow.

Standards now in force

  • Every table ships with RLS enabled and explicit policies before it goes live.
  • Cross-table lookups in policies route through SECURITY DEFINER helpers to prevent recursion.
  • New foreign keys get a covering index in the same migration.
  • Data-quality is monitored automatically, not spot-checked.
  • Every schema change is a named, ordered migration (now mirrored to GitHub).
